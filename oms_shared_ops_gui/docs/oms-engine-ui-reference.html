How OMS Engine finds environments

An environment is anything that appears in at least one of these sources. Nothing is hard-coded — new pods/envs show up on the next refresh automatically. Confidence is a weighted score; below 40 it is listed under Unclassified instead of hidden.

1 · Windows service name pattern weight 40

Toronado host, Get-Service via SSM. Regex ^OMS-(JobManager|AmazonService)-(?<env>[a-z0-9]+?)-(?<pod>\d+)$. Env + pod are parsed from the name, never from a list.

2 · IIS site / app-pool inventory weight 30

Site Manager host, Get-IISSite + bindings. Site name, host header (*.dev.eom.internal) and physical path are all matched; any of them containing an env token counts.

3 · Content share folders weight 20

Content host, directory listing of D:\content\{dev|qa|perf}\* that contains an sm\ or shoplogic\ subfolder. Catches envs that are provisioned but have no service yet.

4 · EC2 tags weight 10

Name, oms:env, oms:pod, oms:arch=v2. Used to discover brand-new V2 stacks (Gamma, podv2, perfv2) before any service exists; a tagged instance auto-adds a host row.

5 · Cross-check & drift flag

If an env is present in one source but missing in another (e.g. IIS site but no JobManager service) it is shown with an amber Partial badge so gaps are visible rather than silently dropped.
